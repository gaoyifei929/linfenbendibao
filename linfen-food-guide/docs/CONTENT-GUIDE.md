# 内容编写指南

## 调性原则

- **亲切接地气**：像朋友推荐，不要写成旅游攻略体
- **真实可信**：标注信息来源，不编造体验
- **实用优先**：价格、地址、营业时间等关键信息必须准确
- **尊重本地**：使用当地人习惯的称呼，避免猎奇视角

## 格式规范

### 店铺描述（note 字段）
- 控制在 50 字以内
- 突出特色或注意事项，例如："汤底浓郁，加辣更香"
- 避免主观评价如"最好吃"，改用客观描述

### 菜品名称（dishes 数组）
- 使用当地通用叫法
- 多个菜品用 `·` 分隔展示，JSON 中为独立字符串

### 标签（tags 数组）
- 用于筛选和搜索，例如：`["老字号", "早餐", "排队"]`
- 不超过 5 个标签

## 来源标注

每条数据应关联 `source` 字段，对应 `sources.json` 中的 id：
- 单一来源：`"source": "douyin-yingying"`
- 多源交叉验证：`"source": "cross-verified"`

## 更新流程

1. 修改 JSON 数据文件
2. 在 CHANGELOG.md 记录变更
3. 如涉及新店铺，确认坐标已转换为 GCJ-02 或标注 coordSystem
